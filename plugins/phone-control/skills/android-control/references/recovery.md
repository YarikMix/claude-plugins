# Восстановление связи

После timeout/обрыва неизвестно, выполнилось ли последнее действие. Сначала попытайся получить свежие PNG/XML из той же сессии, проверь context и смысловой результат. Не повторяй отправку, удаление, покупку или tap только из-за ошибки транспорта.

Если наблюдение тоже недоступно:

1. Прочитай managed sessions, проверь выбранный serial через ADB того же SDK. `unauthorized` требует подтверждения USB-доверия **на Android**, `offline` — проверки кабеля/USB. Разблокировку выполняет человек. Не переключайся на другой найденный телефон.
2. При живом ADB и ошибке instrumentation/UiAutomator2 прочитай конкретный driver log. Не убивай общий ADB server и чужие instrumentation-сессии. Сам факт наличия сессии в `list` не подтверждает её живость.
3. Если подтверждённо умерла собственная сессия, сохрани исход ошибки, удали только её через `appium_session_management({action:"delete",sessionId:S})`, повторно выбери тот же U и создай embedded session с сохранением данных. Один цикл пересоздания; повторная ошибка — диагностика через `setup-android-control`, не цикл переустановок.
4. Новый sessionId означает новые element IDs. Проверь context, получи PNG/XML, установи фактический итог предыдущей команды. Продолжай с наблюдённого состояния.

Пропал SDK на внешнем диске — проверь монтирование и путь в окружении именно MCP; не скачивай SDK повторно до проверки. Изменение env в shell не обновляет уже работающий MCP: нужен reload с учётом его активных сессий. Установка скилла эту проблему не исправляет.
